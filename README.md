# 카드 정산 서버

Node.js + SQLite 카드 정산 웹앱입니다. **봇이 카드사 엑셀을 받아 대기(staging)에 넣고**, 사이트에서 카드별로 **카드내역 불러오기** 한 뒤 분류·이름·메모를 맞춥니다. 정산 완료해도 내역은 삭제하지 않아 가계부/분석에 남습니다.

## 흐름

1. (봇) 카드사 엑셀을 받으면 `POST /api/staging/import` 로 대기열에 넣음  
2. 사이트에서 카드 선택 → **이용금액**·**계좌잔고** 반영 → **입금필요** 확인  
3. **카드내역 불러오기** → 해당 카드 대기 내역이 미정산 목록으로 복사 (중복 스킵, 기존 이력 유지)  
4. 카테고리·내용·메모 수정, 차액은 수기/개인차액 가상내역  
5. 맞춰지면 선택 → **정산완료**

입금필요 = max(0, 이용금액 − 계좌잔고). 352는 계좌잔고를 카드들이 공유합니다.

## 로컬 실행

```bash
cd card-settle-server
npm install
npm start
```

브라우저: http://127.0.0.1:3847  
환경변수: `PORT`(기본 3847), `HOST`(기본 0.0.0.0)

DB: `data/settle.db` (런타임 생성, git 제외)  
샘플: `../card-settle/sample-all-cards.xlsx` 이 있으면 빈 DB일 때 **staging**에만 자동 적재합니다.

```bash
npm run import-sample   # 샘플 → staging (서버 실행 중)
```

## 호스팅

- **GitHub Pages는 Node/SQLite를 돌릴 수 없습니다.** 정적 파일만 가능합니다.
- 이 앱은 **Render / Railway / Fly.io** 같은 Node 호스트에 올리거나, 지금은 이 박스에서 `npm start`로 쓰면 됩니다.
- `npm run build:static` → `dist/` 에 UI 셸만 복사 (API는 별도 서버 필요).

## 주요 API

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/state` | 계좌·카드·규칙·대기 건수 |
| POST | `/api/staging/import` | 봇/스크립트: 엑셀 또는 JSON → staging |
| GET | `/api/staging/:id` | 카드별 대기 미리보기 |
| POST | `/api/cards/:id/load` | staging → txs (불러오기) |
| POST | `/api/upload` | (선택) 엑셀 직접 txs |
| GET/PATCH | `/api/txs` | 내역 조회·분류·이름·메모 |
| POST | `/api/txs/settle` | 정산완료 표시 |

### 정리 기준과 추가 UI

- 계좌 선택 옆의 최근 정리일은 명시적으로 수정하고 상단 저장한 값입니다. 일반 저장·불러오기는 이 날짜를 자동으로 바꾸지 않습니다. 초기 기준은 사용자가 지정한 2026-10-17 01:00 한국시간입니다.
- 금액 입력은 쉼표를 허용하고 변경 시 천단위 서식을 적용합니다. 표 머리글의 정렬은 표시 순서만 바꾸며 계산이나 원본 내역 순서를 바꾸지 않습니다.
- 카드 설정의 개별 카드 표시 이름은 카드사별로 저장합니다. 과거 가계부에는 정산 당시 표시 이름을 남깁니다.
- 수동으로 수정해 저장한 분류는 같은 원본 가맹점·카드사·개별 카드에만 학습합니다. 명시적 규칙, 학습 규칙, 준비된 1차 분류, 기본 규칙 순으로 적용하며 기존 열린 내역이나 가계부를 자동 재분류하지 않습니다. 같은 문맥에 서로 다른 수정이 있으면 규칙 설정에 충돌을 표시합니다. 이 설정도 상단 저장으로 서버에 보관됩니다.
- 정산 표의 체크박스는 선택만 합니다(저장되지 않음). 선택 후 **정산**/**삭제**를 누르면 모든 카드사에서 선택한 내역에 예정 표시를 하고, 상단 **저장**을 눌러야 정산 내역 기록(정산) 또는 제거(삭제, 기록·학습 없음)가 반영됩니다. **전체**는 현재 카드사 내역 선택을 켜고 끕니다.

### 암호화 스테이징 JSON 입력

`node scripts/export-staging-to-docs.js --json /private/prepared.json`은 기존 엑셀 경로 입력과 함께 사용할 수 있는 대체 입력입니다. 개인정보가 들어 있는 JSON과 엑셀은 저장소에 추가하지 않습니다.

JSON은 `cards`에 카드사 ID별 내역 배열을, 선택적인 `issuerUsed`에 명시적으로 확인한 현재 카드 이용금액을 담습니다. 내역은 `date`, `merchant`, `amount`, `category`, `note`, `approval_no`, `cardRef`, `cardLabel`, `datePrecision`, `needsReview`, `classificationReason`을 지원합니다. `cardRef`에는 마스킹된 구분만 사용합니다. 기간별 거래 합계를 현재 이용금액으로 대신 넣으면 안 됩니다. `issuerUsed`의 0은 유효하고, 누락은 사이트에서 기존 이용금액을 유지합니다.

내보내기는 새로 제공한 카드사 내역만 교체하고 다른 카드사의 준비 내역과 기존 설정은 유지합니다. 같은 카드사의 새 이용금액이 생략되면 과거 스테이징 이용금액은 제거합니다. 모든 검증과 암호화가 끝난 뒤 새 암호화 파일을 쓰고 마지막에 메타데이터를 교체하며, 기존 파일을 먼저 삭제하지 않습니다. `--out`은 독립적인 테스트 출력 폴더용입니다. 자동 검증은 `npm run test:pages`이며 실제 개인 자료나 실제 암호 대신 예시 데이터와 별도 임시 폴더를 사용합니다.


불러온 내역의 원화 금액도 직접 수정할 수 있습니다. 최초 불러온 금액은 원본 식별용으로 별도 보존하므로 금액 수정 후 같은 준비 자료를 다시 불러와도 중복으로 넣거나 수정한 금액을 덮어쓰지 않습니다. 환율로 환산한 금액에는 ‘환산 추정’을 표시하고, 직접 금액을 수정하면 현재 금액의 추정 표시는 해제합니다. 원본 환산 근거 메모는 남습니다.

## 서버 저장 (비공개 GitHub 저장소)

- 저장한 전체 상태(내역, 할인 반영 금액/원금액, 정산 기록, 과거 회차, 잔고·안전여유금, 분류·규칙·카드 이름, 최근 정리일)를 입장 암호로 AES-GCM 암호화해 `docs/data/remote.json`이 가리키는 비공개 저장소의 한 파일에 저장합니다. 공개 코드에는 저장소 위치만 있고 토큰은 없습니다.
- 각 브라우저에서 **설정 → 서버 연결·백업**에 그 저장소 하나만 Contents 읽기/쓰기 권한이 있는 세분화 토큰을 입력합니다. 기본은 메모리에만 두고, "기억"을 고르면 입장 암호로 암호화해 이 브라우저에만 보관합니다.
- 상단 저장은 서버가 확인한 뒤에만 "서버 저장됨"으로 바뀝니다. 연결 전이거나 실패·충돌이면 작성 중 내용과 정산·삭제 예정이 그대로 남습니다. 다른 곳에서 먼저 저장했으면 자동으로 덮어쓰거나 합치지 않습니다.
- 처음에는 기존 브라우저에서 **서버로 처음 올리기**로 이 브라우저 저장본만 명시적으로 올립니다(저장 안 된 변경은 제외). 서버 데이터와 브라우저 저장본이 다르면 백업 후 직접 선택합니다.


## Pages UI v3 업데이트 (2026-11-11)

**업데이트 후 모든 컴퓨터·휴대폰의 모든 열린 탭을 새로고침한 뒤 사용하세요.**
이전 화면은 새 분류 ID 형식을 이해하지 못하므로, 이전 탭에서 계속 편집·저장하지 마세요.
기존 연결과 저장본은 유지되며 최초 업로드를 다시 할 필요가 없습니다.

- 체크는 여러 카드사·계좌를 이동해도 유지되는 임시 선택입니다. 스크롤에 고정되는 도구 모음에 **선택 합계(건수·금액)**를 표시하고, 여러 카드사면 카드사별 금액과 결제계좌도 표시합니다. **정산 / 삭제**는 모든 선택에 적용하며 다른 카드사 선택이 포함되면 확인합니다. **전체**는 현재 카드사의 아직 예정 처리되지 않은 내역만 선택합니다.
- 정산·삭제 예정 행은 체크된 상태로 남습니다. 저장 전에 체크를 해제하거나 행의 **취소**를 누르면 예정을 취소할 수 있습니다. 예정 행은 선택 합계에서 빠집니다.
- 정산·삭제 예정은 남겨둔 내역 합계에서 즉시 빠지므로 카드·계좌·사이드바 금액이 저장 전에도 미리 계산됩니다. 실제 가계부 기록, 분류 학습과 서버 저장은 여전히 상단 **저장**에서만 이루어집니다. 실패·충돌 때에는 예정과 작성 중 내용이 유지됩니다.
- Pages 계산식: **카드 입금금액 = 이용금액 − 남겨둔 내역합**, **계좌 입금금액 = 카드별 입금금액 합 + 안전여유금**, **입금필요 = 계좌 입금금액 − 현재잔고**. 음수도 그대로 표시하며 안전여유금 0은 유효합니다. 위 Node API 소개와 별개의 Pages 계산식입니다.
- 분류는 고정 ID와 표시 이름을 분리했습니다. 이름을 바꾸면 이전 가계부·분류합계·규칙·CSV 이름도 바뀝니다. 가계부·내역·규칙·학습 충돌에서 사용 중인 분류는 삭제할 수 없습니다. 색상과 순서도 ID에 연결됩니다.
- 연결·최초 업로드·저장본/작성 중 백업·충돌 해결은 **설정 → 서버 연결·백업**에서 계속 사용할 수 있습니다. 정상 연결은 작은 상태 문구만 표시하고 연결 필요·실패·충돌·확인 필요에만 별도 버튼을 표시합니다.

### 데이터 형식과 안전성

상태의 `v`는 3입니다. `cats`는 표시 순서의 ID 배열이고, `catNames`/`catColors`는 ID별 이름/색상입니다. 거래·가계부·수동/학습 규칙·충돌은 ID를 참조합니다. 원래 준비자료·config의 이름은 `catAliases`로 기존 ID에 연결되므로 분류를 바꾼 뒤 불러와도 같은 분류를 유지합니다. 새 분류가 예전 표시 이름을 사용해도 기존 ID는 재사용하지 않습니다.

기존 문자열 분류는 전체 문자열의 UTF-16 인코딩으로 결정적인 ID를 만듭니다(해시 충돌 없음). 목록에 없던 거래·가계부·규칙·색상 분류도 보존합니다. 마이그레이션은 멱등적인 메모리 변환이며 금액·원본 금액·기록은 바꾸지 않습니다. 이후 명시적인 저장에서 새 형식을 기록합니다.

브라우저 저장 키는 의도적으로 `card-settle-pages-v2`를 유지합니다. 연결 신뢰 표시는 **원본 localStorage 바이트**의 fingerprint로 검증하므로, 시작 시 마이그레이션 결과를 localStorage에 쓰거나 신뢰 표시를 다시 만들지 않습니다. 시작·자동 연결에는 서버 쓰기가 없고, 기존 충돌/SHA·saveId 확인·실패 보존 방식은 유지합니다. 마이그레이션을 위해 비공개 자료 저장소를 직접 읽거나 수정하는 작업은 필요하지 않습니다.

### 검증

`npm run test:pages`는 합성 자료만으로 기존 편집·정렬·학습·중복 방지·서버 저장 안전성 및 v3 회귀를 검사합니다. v3 검사는 현실적인 이전 형식, 알려지지 않은 분류·과거 기록·규칙·색상, 신뢰 연결의 무쓰기 자동 불러오기, 암호화 저장 왕복, 과거 분류 표시/CSV, 계좌를 넘는 선택·확인·취소, 음수/안전여유금 0, 저장 전후 미리보기 일치, 정산 1회 기록과 삭제 시 학습 없음 등을 포함합니다.
